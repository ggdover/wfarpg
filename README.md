# wfarpg

An action RPG in the making, set in a low-poly Swedish pine forest: a Godot 4.7 game whose models, textures and
layouts are generated by Python scripts in Blender 5.2. For now it's a play demo of twelve scenes (`game/`). The
project notes are in `CLAUDE.md`, and each folder's README says more.

## Linux and Windows

The project is developed and test-run on both Linux (Ubuntu) and Windows, and everything in it works the same on
both. The commands in the READMEs are the same on both too, given these tools on PATH:

| Tool | For | Linux | Windows |
|---|---|---|---|
| Godot 4.7, the standard build (not .NET) | the game | `godot`, e.g. in `~/.local/bin` | `godot`: the console build, `Godot_v4.7.2-stable_win64_console.exe`, through a `godot.cmd` (below) |
| Blender 5.2 | models, textures, layouts | `blender` | `blender`: its folder, e.g. `C:\Program Files\Blender Foundation\Blender 5.2`, on PATH |
| Python 3 with Pillow | the tools, and the scripts that draw images | `python3`, with Pillow (`sudo apt install python3-pil`) | the Python install manager from python.org, which brings `python3` as well as `py`; then `python3 -m pip install pillow` |
| Google Chrome or Chromium | the mockups' HUD and blueprint labels | `google-chrome` or `chromium` | found where it installs itself |
| Git | | `git` | Git for Windows, with Git Bash |

Run the commands from the repository's root, or from the folder a README names, in any terminal: bash on Linux;
PowerShell, cmd or Git Bash on Windows. `GODOT`, `CHROME` and `PYTHON` point the tools at another Godot, Chrome or
Python.

On Windows, Godot comes as two programs, and the console build is the one for the command line: its output and exit
code reach the terminal, and it opens the game's window all the same. To have it as `godot`, put a `godot.cmd` in a
folder on PATH, such as `%USERPROFILE%\.local\bin`, for PowerShell and cmd:

```bat
@echo off
"C:\<Godot's folder>\Godot_v4.7.2-stable_win64_console.exe" %*
exit /b %errorlevel%
```

and a `godot` beside it for Git Bash:

```sh
#!/bin/sh
exec "/c/<Godot's folder>/Godot_v4.7.2-stable_win64_console.exe" "$@"
```

## Playing and checking

```sh
godot --path game                   # the demo; the first run imports its models and textures
python3 game/tools/checks.py        # the checks: the import, the selftest and every scene's scenetest
```

`game/README.md` has the demo's controls and options. The checks open the demo's window for each of them, a few
minutes in all, and end with how many passed: run them after a change, on whichever machine is at hand.

## Rebuilding and exporting

- The game's models, textures and layouts: `game/README.md`, Rebuilding the assets.
- The trees and plants: `assets/trees/README.md` and `assets/plants/README.md`.
- The mockups and the design history: `mockups/README.md`.
- `python3 game/tools/export_windows.py` builds `dist/wfarpg.exe`, the whole demo for Windows in one file, on Linux
  or Windows (`game/README.md`, The Windows build).

What keeps the project working on both, for whoever changes it, is in `CLAUDE.md`, Linux and Windows.
